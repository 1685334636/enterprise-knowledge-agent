## 选择第3题：企业知识问答 Agent

目标是在可审阅的小项目中完整表现“检索观察 → 补查/读原文 → 回答/澄清/停止”的循环。选择该题是因为引用正确性、冲突处理、工具失败与相似问法都有明确可执行的验收标准，业务工具可用合成资料完整实现，范围适合建议的约3小时投入。

本次只实现第3题。交付为本地 Python CLI；不实施其他三题，不部署网站，不连接真实企业资料，不推送 GitHub。后续是否上传仓库由用户另行决定。

初始阶段按用户选择先验证离线Mock；2026-10-29用户提供项目外DeepSeek密钥文件，授权在本地完整测试。两个阶段分别记录，不把Mock Trace当作真实模型证据。GitHub仍等待用户后续命令。

## 工作顺序

|阶段|产物|完成标准|预估投入|
|---|---|---|---:|
|1. 阅读与拆解|本文件、01需求、02方案|题目每个必验点都有对应验收编号|20分钟|
|2. 工具与数据|合成制度、检索、片段读取|可替换资料、可注入失败、不读取任意路径|25分钟|
|3. Agent循环|协议、Mock、真实接口、状态与上限|动作来自适配器；工具观察进入下一次决策|35分钟|
|4. 证据边界|原文引用校验、冲突与状态校验|不伪造引用，不默认以新版覆盖旧版|25分钟|
|5. 验证与样例|测试、输入/输出/JSONL Trace|覆盖全部必验点及至少两条不同路径|35分钟|
|6. 文档与核对|README、03评估、04AI使用、05复盘|可复制运行，结果与文件相互对应|20分钟|

以上为计划投入，不冒充笔试平台计时或候选人的实际用时。实际自动执行耗时写入样例评估产物，并明确统计范围。

## 文档规范

1. 使用 UTF-8 Markdown；所有相对链接以所在文件为基准。代码、数据、文档均使用合成内容，不收录试题截图、手机号、密钥或企业私密资料。
2. README 是运行和审阅入口；docs/01–05 分别负责需求、设计、评估、AI使用记录和复盘，避免重复堆砌。
3. 需求以 R 编号，验收以 A 编号；评估表引用相同编号，链接 examples/ 下的真实输出与 Trace。
4. “计划”“已实现”“已验证”“尚未验证”明确区分。失败必须保留失败状态，未运行项目不得写通过。
5. 所有关键选择说明原因、替代方案和局限；不以框架名称代替设计解释。
6. Trace 仅记录简短动作依据、工具参数、观察摘要、后续决策及最终状态，不记录或要求模型内部思维链。
7. AI使用记录如实说明 AI 生成和执行的范围；用户尚未进行的手工修改、审核和验证不得编造。
