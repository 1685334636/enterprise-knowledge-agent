# 产品需求分析

## 用户、问题和目标

用户是需要查询制度或产品事实的员工。普通关键词检索只能列文档，直接生成答案容易忽略适用范围、制度冲突或缺乏证据。产品应找到相关制度、读取原文，并输出可核验的答案；当资料不足、互相矛盾或工具失败时明确停留在相应状态。

核心成功标准：答案中的制度事实全部来自本次工具已读取的原文；同主题冲突不得擅自按日期选择；运行记录可说明为何补查、为何停止。当前交付优先验证这些边界，不追求聊天界面。

## 范围

包含：中文问题、可选对话历史、带文档ID和版本日期的合成制度、全文检索、片段读取、动态动作循环、引用和冲突约束、CLI、JSON输出、JSONL Trace、运行上限、测试与离线样例。

不包含：企业权限系统、真实知识库同步、多模态解析、真实发布或其他外部写操作、GitHub上传、生产环境检索质量承诺。真实模型接口可配置，但本轮只验离线 Mock。

## 输入与输出契约

输入：`question` 为非空中文或英文问题；`history` 为可选的用户/助手消息；资料目录内使用 JSON 维护合成文档与片段。文档含ID、标题、版本日期、适用范围、原文片段和人工标注事实键；标注用于有限域冲突核对，不由程序猜测原文事实。

输出：任务状态、答案、引用（文档ID、版本、片段ID、原文）、资料缺口、澄清问题、工具调用次数和决策步数、运行模式。只在证据约束通过后输出已回答状态。

任务状态：`answered`、`conflict`、`needs_clarification`、`insufficient_evidence`、`tool_error`、`model_error`、`limit_reached`。异常不得伪装成成功。

## 功能与验收矩阵

|需求|功能|验收编号与可观察结果|
|---|---|---|
|R01|检索并读取制度原文|A01 明确问题：回答0.5天等原文事实，附有效文档/片段ID|
|R02|冲突展示及适用范围澄清|A02 报销30/15天并存：列出双方引用并请求确认，不能直接选15天|
|R03|没有证据时停止|A03 资料外问题：说明资料缺口，不虚构答案|
|R04|相同意思的问法可检索|A04 改写后问题：仍找到同一制度依据|
|R05|利用上下文消解追问|A05 年假后的“那实习生呢”：查询实习生适用范围并给出依据|
|R06|模型观察工具失败后调整动作|A06 注入一次检索失败：下一步调整查询；持续失败则明确失败|
|R07|有界决策循环|A07 步数或工具次数耗尽：返回limit_reached及未完成原因|
|R08|引用必须来自已读取片段|A08 捏造ID、捏造引文、仅搜索未读取时均不能直接回答|
|R09|资料变化影响输出|A09 去掉冲突文档后可回答30天；替换期限后答案随原文变化|
|R10|完整可审核运行证据|A10 至少3组输入、实际输出及Trace，覆盖全部必验点和至少2条不同执行路径|
|R11|数据与运行边界|A11 文档内容视为资料，不能成为系统指令；工具不能读取任意文件|

## 验收口径与边界

“可靠”在本项目中指引用真实性、原文读取、有限域冲突标注和明确失败状态；不声称解决开放域语义蕴含问题。答案采用保守的原文摘录式表达，避免无证据扩写。

Mock 验收证明检索、循环、状态、边界与日志实现可运行，不证明真实语言模型在新问题上的决策能力。接入真实模型后需要重新生成并审阅相同用例的 Trace。
